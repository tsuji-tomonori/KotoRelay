# UI改訂の採用方針

利用者が2026年9月12日に提供した「KotoRelay-デザイン設計パッケージ」を根拠に、緑のブランドを保ったまま文書中心の業務UIへ改訂する。元ZIPと画面案HTMLはローカルの `.workspace` に保管し、Gitの管理対象に含めない。

- 文字はUI16px、本文18px、補助14px。本文リンクは青と下線、フォーカスは黄と黒、操作は原則44px以上。320・390・768・1440pxで機能を維持する。
- ヘッダーの利用部署とアカウントを常時利用可能にし、役割別ナビを表示する。利用部署は閲覧・質問の帰属、管理部署は文書・統計・所属の対象として区別する。
- 全体の未保存確認、編集入力の保持、読み込み・空・検索0件・失敗の区別を統一する。
- 閲覧・執筆プレビュー・審査は同じ版の本文と画像を同じレンダラーで表示する。文字位置はUnicodeコードポイント数で定義する。重複見出しにも一意の目次を付ける。
- OCRは領域ID単位で訂正する。位置と大きさを数値で編集でき、追加・削除は明示操作にする。手入力の確信度は未測定とする。旧JSONの安定IDは読取時だけ補い、承認済みmanifestとハッシュは書き換えない。
- 画像のalt・説明文は配置情報として下書きと確定版へ含める。画像上限は提案当時の5MiBではなく、最新実装の3MiB・20MP・各辺8000px・文書10枚を維持する。
- 引用の文書ID・版ID・チャンクIDを保持し、公開版が異なる場合は更新を説明して明示的に最新版へ移動する。旧版の一般公開は追加しない。
- 部署別一覧はAPIで認可し、SQLで絞り込んでからページングする。公開版と最新申請の番号・状態を分離して返し、`has_next`で最終ページを判定する。従来の配列レスポンスは互換用に保持し、UIは`page=true`のページ形式を使用する。
- 公開設定は変更前後を確認して保存する。削除理由はAPIで必須とし、状態変更と同じtransactionで監査へ保存する。入力フォームは確認ダイアログの外に置く。
- 会話の利用部署を途中で混在させず、部署変更は新規会話として扱う。反映ジョブと削除ジョブの状態辞書を分ける。

原設計のF01〜F16とT01〜T12を上記へ対応させる。SQL・APIの回帰はpytestと実PostgreSQL、部品の挙動はVitest、操作・フォーカス・画像・320pxでのリフローはCompose Playwrightで検証する。ブラウザのARIA構造を検査するが、実スクリーンリーダーによる読み上げ品質やWCAG全体への適合は未確認として扱う。

参照：[DADS タイポグラフィ](https://design.digital.go.jp/dads/foundations/typography/)、[DADS モーダルダイアログ](https://design.digital.go.jp/dads/components/modal-dialog/)。フレームワークとクラウド構成は既存のものを使用する。
